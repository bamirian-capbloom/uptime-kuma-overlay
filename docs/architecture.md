# Architecture and extension contract

The top-level JSON manifest pins official source commit/tree, observed fork reference commit/tree, corrected intended output tree and module order. Each module manifest has a SHA-256 in the root manifest; each patch has a SHA-256, explicit predecessor IDs, before/after Git tree SHAs, full changed-file inventory, source PR and documentation link. Full Git tree comparison catches missing, extra, altered or executable-bit changes, including unrelated divergence. These checks detect mistakes and corruption, not a malicious rewrite of this repository: review manifest changes alongside patches.

Seven original logical units preserve the reviewed PR boundaries, and unit 0006a corrects a clone-payload regression discovered during validation and unit 0006b adds the issue #2 dashboard suppression explanation. These units follow a strict tree chain. Only complete module selections are supported. `monitor-dependencies` is the common substrate; `toast-lifecycle` requires it. Graph ordering is explicit and cycles, duplicate IDs, missing requirements and incompatible tree chains are rejected. This is extensible but is not a universal patch solver: a future independently optional module that overlaps another module's files may require combination-specific manifests/tree checkpoints. Unsupported combinations fail rather than improvise a merge.

The driver validates manifests/checksums/docs before cloning, uses a new independent clone, checks out the exact upstream commit, checks each patch against the index, applies without three-way conflict resolution and compares every resulting tree. For the default selection, a separate index reverses only the declared additional units (the clone correction and dashboard enhancement) and must reconstruct the original fork tree; the full resulting file delta must equal the documented allowlist. A deterministic local commit anchors the output; it is not a signed upstream commit. Any failure cleans up the temporary checkout; existing destinations, including symlinks, are rejected. Publication reserves a new destination and atomically renames the completed tree. Every Git subprocess (including initialization, alternate-index proof, deterministic commit and validation status checks) clears inherited repository-local variables and environment-injected configuration before execution. The alternate index and commit identity are then supplied only as explicit internal overrides. SSH/credential helpers, TLS settings and other transport configuration remain available. Validation subprocesses receive the same isolated environment. Source checkouts, their dirty files, branches and staging indexes are never reset. Git and repository content must be trusted; run application tests only for code you intend to execute.

Tests live at their normal upstream paths inside the patches, so the exact fork regression suite is reproduced. Per-unit docs explain behavior, touched files/functions, dependencies, API/schema effects, baseline, conflict hotspots, tests and retirement. Historical test reports are preserved as fork provenance; current evidence is maintained separately in validation.md.

To add a module: start a clean pinned replay of its declared predecessors, implement and review the feature with tests, generate binary/full-index diffs, document every logical unit, and record input/output trees and checksums. Add its manifest to the root with a checksum and select it in CI. Explicitly test each supported feature combination, invalid dependency selections, clean installs and rollback. Do not just append an unverified patch, auto-update hashes after failures, use `git apply --3way`, or broaden the baseline silently. Update all affected module checksums after a reviewed manifest edit.
